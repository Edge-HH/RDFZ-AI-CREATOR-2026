# 0002 用可变剧情节点替代固定回合灾难循环

## 状态

已采纳（2026-10-06）

## 背景

旧版本固定为 6 个主回合，每回合都要求玩家先选方案、再处理一次突发事件，导致上手信息过载、灾难节奏单调，随机性只改变事件顺序，主线仍然固定。

## 决定

1. 一局由 4–6 个剧情节点组成，节点数量和支线顺序由确定性随机种子决定；复杂度放在节点内的对白、证据和关系分支。
2. 三份关键证据节点和终局节点必须存在可达路径；调查、通信、关系、后勤、平静和危机节点按幕和前置条件抽取。
3. 每个节点由一个主行动和一个回应组成。前两个节点不因资源不足失败，危机受风险压力控制，不再每个节点强制出现。
4. 顶部只显示能源、生命支持、物资和信任四项资源。证据、人物关系、地下城支持度、空间站控制权、Luna 权限和人类自主性作为剧情状态或结局指标。
5. 对话框自动播放节点对白，回应结算对白结束后自动进入下一节点；点击跳过和立即推进作为辅助操作。
6. Luna 继续使用规则驱动、离线、可解释的建议模型；节点状态机和 `act(state, action)` reducer 不依赖 DOM，`replay(seed, actions)` 保持可复盘。

## 后果

- 复杂度从资源数量转移到证据、人物关系和三地通信的逻辑依赖；
- 新玩家可以在低风险第一节点学习操作，熟练玩家通过不同种子和支线获得重玩价值；
- 关键节点保证可达，随机性不会把玩家锁死在无法完成的剧情路径上；
- 剧情节点集中在 `src/data/storyNodes.ts`，便于继续扩写内容和测试前置条件。
