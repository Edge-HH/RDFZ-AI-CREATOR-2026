# 《灰环点火》创作圣经（当前垂直切片）

> 版本：0.1（方案稿）
> 定位：原创科幻策略叙事游戏；对话即决策；Three.js 响应式网页
> 适用范围：一次 15–20 分钟的关键救援任务

## 0. 改编边界与创作声明

本项目只借鉴“地球迁徙时代、运送关键能源部件、抢修行星发动机”的宏观母题，不复制电影角色、原台词、镜头、配乐、道具外观、事件顺序或专有设定。公开参赛和部署版本使用本文件中的原创角色、地点、组织、任务名和视觉资产。

游戏中的“环弧—7 行星推力塔”和“脉冲点火芯”属于原创未来设定。现实科学只用于约束低温、地形、能源、通信、车辆负载和人员安全等可解释变量；行星迁移、推力塔规模和点火芯能力明确标注为游戏化假设。

## 1. 种子陈述（S1）

在地球轨道迁移的第 17 年，白弧盆地的环弧—7 行星推力塔突然冷停机。现场系统工程师林岑带领四名队员，在 18 个任务小时内把一枚超导脉冲点火芯送到塔下，并决定究竟把有限的冷却、能源和人员安全留给这一座塔，还是留给下一座可能同样失效的塔。

玩家玩完后应记住：**拯救不是按下一个按钮，而是在没有完美答案时，让每一个选择仍然值得负责。**

## 2. 世界观画布（S2）

### 核心前提

太阳辐射长期升高，地球需要通过分布式行星推力塔进行缓慢轨道修正。每座塔都不能独立“推动地球”，但多座塔组成的推力网络能把轨道修正窗口维持在可接受范围内。一座塔停机不会立即毁灭地球，却会压缩下一次窗口；连续故障会迫使地下城进入更严格的能源和人口配给。

### 地理

白弧盆地是一个虚构的高原冰原与地热裂谷复合区。北部为短而陡的冰脊，南部是有裂缝的风蚀台地，西侧有可避风但距离更长的地热沟，塔区下方存在一段早期维护井道。地图只使用坡度、距离、温度、风速、地表承载力和通信视距等参数，不直接使用现实中国地图。

### 当前紧张态势

环弧—7 的磁约束推进腔出现低温泄漏，自动系统为了避免失控而进入冷停机。塔端旧固件与新一代点火芯的校准码不完全兼容；任务不是把芯送到就结束，而是要在到达前完成低温预校准，并在塔下决定采用保守重启还是高风险旁路。

### 技术能力与代价

* 推力塔使用“惯性聚变推力阵列”作为游戏中的未来技术假设，必须持续进行磁体冷却和热交换。
* 点火芯是密封的超导脉冲组件，怕剧烈振动、持续升温和错误校准；拆开外壳可以临时取出导管，却会增加污染和失效风险。
* 车队能源来自电池和小型燃料电池。能源可用于驱动车辆、维持通信中继、给无人机充电和支持冷却泵，不能无限补充。
* 远程通信依赖地形视距和中继节点。背坡、地热蒸汽和磁扰会让信息变慢或缺失；失联时玩家仍能行动，但预估信息的可信度下降。
* 低温、疲劳和负载会共同放大机械故障概率。游戏采用可解释的简化公式，所有缩放参数写进 README 的游戏规则说明。

### 主角所在阶层

林岑不是总部决策者，也没有无限权限。她是能在现场打开设备、判断故障和把命令翻译成动作的系统工程师。她拥有一次“暂停确认”权限：可以要求队友给出实测数据，但每次暂停都会消耗任务时间。

### 文化禁忌

迁徙时代最忌讳把伤亡写成“系统误差”。每一名失去行动能力的队员都必须被记录、解释和带回；任何“为了大局自动抹掉个人代价”的报告都可能造成信任崩溃。这个禁忌会在结算页变成玩家对维修记录的署名选择。

## 3. 现实依据与游戏化假设

| 现实依据（用于约束） | 游戏化表达 | 明确不宣称的部分 |
|---|---|---|
| 低温会改变材料性能、润滑和人员操作能力 | 温度越低，车辆耗能、维修耗材和疲劳风险越高 | 不把数值当作真实工程规范 |
| 山地/冰原的坡度、路程和承载力影响车辆行驶 | 三维态势窗显示坡度、距离、预计耗能和打滑风险 | 白弧盆地不是现实地点测绘结果 |
| 通信需要视距、功率和中继 | 背坡或磁扰时通信置信度下降，远程选项减少 | 不模拟真实通信协议和真实延迟 |
| 高能设备需要冷却、冗余和故障隔离 | 冷却桶、电池、旁路和降功率重启形成资源取舍 | 行星级推力塔与点火芯是未来假设 |
| 长时间封闭任务会积累疲劳和医疗压力 | 人员状态影响操作成功率和可用行动 | 不替代医学或航天安全指南 |

## 4. 核心理念（S3）

**当资源不可能同时满足时间、能源、设备和人的安全时，责任不是找到零代价答案，而是公开承担取舍并让团队共同完成下一步。**

它会约束剧情：任何捷径都必须留下可见代价；任何牺牲都不能被系统自动美化；玩家的选择必须在后续对话、资源曲线或结局报告中被记住。

## 5. 主要角色（S5）

### 林岑｜玩家，现场系统工程师

* 一句话特质：她是那种会在所有人催她启动时，先把手伸进发烫的控制柜确认保险栓的人。
* 伤口：早年的一次抢修中，她按总部规定等待完整数据，错过了一个可以手动隔离故障的窗口。
* 谎言：只要把数据补齐、把风险算清，就不会有人为决定负责。
* 渴望：用一次完美诊断证明自己再也不会错。
* 需要：承认现场永远存在未知，并把判断权交给可以共同承受后果的人。
* 声音：短句、先说参数再说感受；越害怕越准确。

### 裴衡｜车队长、前地质测绘员

* 一句话特质：他会把最危险的路线叫作“省下来的时间”，却从不把队员叫作“可接受损耗”。
* 伤口：曾带队在一条安全但过慢的路线中失去补给窗口。
* 谎言：只要车队不停，所有人就还有选择。
* 渴望：用速度换回对车队的控制感。
* 需要：接受停下来也是一种主动行动。
* 声音：地质术语、简短反问、很少直接说“我担心”。

### 沈葵｜磁约束与冷却专员

* 一句话特质：她宁愿让一台设备晚十分钟启动，也不愿让一个没有校准的数字进入记录。
* 伤口：见过未经校准的冷却阀导致一整排维护舱报废。
* 谎言：严谨足够多，就能把事故挡在门外。
* 渴望：把每个隐患都提前关掉。
* 需要：在无法完整验证时，学会提出有边界的冒险方案。
* 声音：语速平稳，常纠正别人的单位；情绪上升时反而更轻。

### 阿阮｜医疗与无人机通信员

* 一句话特质：她会在频道里替每个人报体征，却从不报自己的手在发抖。
* 伤口：曾因通信中断晚收到伤员位置，失去了一名队友。
* 谎言：只要信息保持完整，人就不会被当成数字。
* 渴望：让所有人的状态都被看见。
* 需要：接受信息永远可能不完整，并在不完整中做出及时行动。
* 声音：称呼具体的人名，少用抽象名词；会用平静语气打断争吵。

### 周砾｜塔区维护老兵、路线向导

* 一句话特质：他记得每一口旧井道的回声，却不相信任何一份由总部签发的“安全”。
* 伤口：年轻时被系统从一次维修名单中划掉，后来亲眼见到那支小队被封在旧井道。
* 谎言：所有宏大计划最终都会把具体的人丢在黑暗里。
* 渴望：把这次任务变成一次对总部的反证。
* 需要：承认留下维修记录、让别人接手判断，也是对死者负责。
* 声音：方位感强，使用旧设施俗称；关键时刻不讲完整句。

## 6. 玩法叙事骨架

### 可见状态

* `time`：剩余任务分钟，初始 1080（18 小时）。
* `energy`：车队电池与燃料电池合计，初始 100。
* `supplies`：冷却桶、维修件、锚索和医疗包的统一物资值，初始 80。
* `crew`：五名队员的可用程度，显示健康、疲劳和是否受伤，不用死亡动画。
* `safety`：0–100 安全裕度；越低，事件风险越高，队友对白越紧张。
* `engineStability`：塔端稳定度；到达 60 以上才可能完成启动。
* `trust`：团队信任，范围 0–100；影响是否能执行协同方案和结算语气。

### 每轮循环

1. **通信对话**：队员报告新信息，玩家选择回应方式。回应决定当前行动意图，不是知识问答。
2. **态势观察**：玩家在 Three.js 窗口点选路线或设备节点，查看坡度、距离、温度、风速、通信置信度和预估代价。
3. **方案确认**：选择一个主行动和一个保障行动；系统显示“预计变化”和信息可信度，确认后不可撤销。
4. **执行反馈**：车辆、无人机、冷却管线或发动机腔体播放短动画；资源即时结算，事件解释“因为—所以”的因果链。
5. **对话回声**：队员根据实际结果回应，开放下一节点或关闭某个方案。

### 选择与数值示例

| 决策 | 结果（示例缩放值） | 后续记忆 |
|---|---|---|
| 南坡冰脊：停 4 分钟布设锚索 | `time -4`、`safety +10`、`supplies -6` | 塔下校准窗口缩短，但周砾更愿意共享旧井道 |
| 南坡冰脊：直接通过 | `time -0`、`energy -10`、`safety -14` | 可能触发打滑，沈葵后续维修预估更悲观 |
| 西侧地热沟：低速绕行 | `time -22`、`energy -18`、`safety +6` | 保持通信，但冷却桶消耗增加 |
| 启用备用中继 | `energy -12`、`supplies -4`、`trust +4` | 解锁远程对齐方案，屏幕获得更完整数据 |
| 让无人机先探路 | `energy -8`、`time -3`；成功时 `safety +5` | 失败会让通信置信度下降，不是纯随机惩罚 |
| 旁路直连点火 | `time +12`、`engineStability +24`、`safety -22` | 若冷却冗余不足，可能进入“带伤续航”或“静默灯”结局 |
| 保守降功率重启 | `time -18`、`engineStability +14`、`safety +12` | 需要队员承担更久的低温暴露，但信任更稳定 |

数值只用于可读的游戏化缩放，不代表真实工程参数。所有效果都由配置表驱动，不能把关键结果藏在不可解释的随机数里。

## 7. 任务流程与详细情节（S4/S6）

### 序章：冷停机警报（场景 0）

* **目标**：确认任务不是普通送货，而是一次会改变全队生存余量的抢修。
* **冲突**：塔端自动系统进入冷停机，通信只剩断续语音；总控要求 18 小时内送达点火芯，现场数据显示点火芯校准码不兼容。
* **灾难**：林岑发现运输舱的温度记录少了一段，无法确认点火芯是否已经受过热冲击。
* **玩家动作**：直接出发（节省 8 分钟）或暂停做低温扫描（消耗 8 分钟，获得更可靠的校准信息）。
* **演出**：黑屏先出红色状态码；警报声停止后只留下冷却泵的脉冲声；对话框显示“频道 03｜塔区值守”。

**对白示例**

> 裴衡：白弧盆地的风已经换向。我们现在走，六分钟后出不了门。
> 沈葵：那不是“能不能出门”，是“出门以后还能不能把芯带回来”。
> 阿阮：林岑，先报你看到的，不要报系统希望你看到的。
> 林岑（玩家选项）：
> A. “扫描。八分钟由我负责。”（`time -8`，校准置信度上升）
> B. “装舱，边走边测。”（`time -0`，后续风险区间扩大）
> C. “先问塔区值守，为什么记录缺了一段。”（`trust +5`，开启隐藏对话；`time -5`）

### 第一幕：装载与路线（场景 1–2）

**场景 1：只能带两件**

车队总载荷不足以同时带足备用冷却桶、加大电池、锚索和医疗包。玩家在对话中拖动资源分配条，再确认装载。每个方案都会在三维车队模型上改变重量和后续路线预估。

* 带备用冷却桶：塔下容错高，车辆耗能增加。
* 带加大电池：路线选择自由，医疗和锚索不足。
* 带医疗包与锚索：人员安全高，点火芯冷却冗余低。

**场景 2：两条路线**

* **南坡冰脊**：距离短、坡度高、裂缝风险高；更适合“停下布锚”或“赌车况”。
* **西侧地热沟**：距离长、坡度低、蒸汽会干扰传感器；更适合“带足电量”或“依靠周砾的旧井道记忆”。

场景结尾的灾难不是“选错路线”，而是两条路线都在变化：南坡冰架开始错层，西线地热喷口提前开启。玩家的选择决定接下来风险以哪种形式出现。

### 第二幕：风险兑现与中点翻转（场景 3–5）

**场景 3：冰架错层/地热泄漏**

路线事件由前一幕选择决定。玩家可以减载、停下布锚、让无人机探路、使用备用冷却或拆点火芯导管。每个行动都立即影响时间、能源、物资或安全，并写入因果日志。

**场景 4：中继失联**

背坡或地热蒸汽让通信置信度降低。阿阮请求启用备用中继，裴衡认为这会耗掉最后一段爬坡所需的电。玩家可以让车队盲行、先搭中继、或让周砾进入旧井道寻找有线接口。此场景改变的是信息质量和队友信任，而不只是资源条。

**场景 5：中点翻转——芯与塔不兼容**

沈葵在低温预校准时发现，点火芯的校准码和塔端旧固件有一位校验位不一致。总部没有备用固件，塔区值守也承认此前隐瞒了冷却泄漏。任务从“把芯送到”变成“决定是否用不完全兼容的芯点火”。

* **停下完成校准**：时间减少，提升发动机稳定度和安全。
* **边走边校准**：保留时间，但将错误概率转化为塔下更高风险。
* **相信旧井道手动接口**：依赖周砾，若信任足够可获得安全捷径，否则触发通信与人员风险。

这一场把林岑从“执行总部任务”推向“为现场判断署名”，完成主角从谨慎等待到主动负责的弧线转折。

### 第三幕：塔下点火（场景 6–7）

**场景 6：磁约束腔失超**

到达塔下后，余震让推进腔的磁体进入失超预警。玩家必须在有限时间内安排净化、对齐、冷却和人员分工。三维态势窗显示推进腔剖面、热区、可用维护口和当前通信链路。

* 保守方案：先泄压、降输出再点火；耗时多，安全高。
* 旁路直连：跳过完整净化；速度快，人员和设备风险高。
* 远程分工：让无人机和周砾进腔，林岑留在控制台；设备耐久下降，但人员安全更高。

**场景 7：最后一枚冷却芯**

塔端要求把最后一枚冷却芯全部投入本塔；阿阮提醒下一座塔的补给车还没有消息。玩家可以全部投入、保留一半、或以人员安全为条件延迟点火。这里没有隐藏“标准答案”，结局由发动机稳定度、人员状态、资源余量和信任共同决定。

## 8. 结局与重玩

结局根据 `engineStability`、`safety`、`crew`、`time` 和 `trust` 组合判定，避免简单的“选对/选错”。

1. **稳态迁移**：塔以降功率稳定重启，小队全员或仅轻伤，下一次轨道窗口被保住。结算展示完整的因果链和维修记录署名。
2. **带伤续航**：塔成功点火，但有人重伤或物资耗尽；地球获得数小时缓冲，玩家必须在报告中承认代价。
3. **冷启动成功**：旁路方案成功，推力恢复到高位，但安全裕度和团队信任跌至危险区；结算评价强调“成功不等于正确”。
4. **静默灯**：塔未能点火，点火芯和维修记录被送回，车队保住大部分人员；失败页面给出下一任务线索，不把失败写成无意义 Game Over。

重玩保留已解锁的维修日志和角色语音记录，但中段险阻参数使用固定种子加一个可控扰动，玩家不能只背答案。结算页提供“本局路线/资源/人员状态”曲线与关键决定时间线。

## 9. 系统化对白池

同一节点根据状态准备 5–10 条短变体，防止重玩时出现静态对话墙：

* 首次启用中继：阿阮先报信号，再问“你要看见全部，还是先让车走？”
* 已失去一箱物资：裴衡把“减载”改称“把重量留给下一段路”。
* `trust < 35`：周砾只给方向，不给理由；玩家必须花时间请求实测。
* `safety < 25`：沈葵不再纠正单位，只问“谁还站得住？”
* 重玩同种子：系统在不打断玩家的情况下标记“你曾经在这里停过”。

所有对白写作遵循：潜台词优先；角色用词、句长和打断方式可区分；信息通过冲突和后果出现；每场戏有目标、冲突和灾难，灾难后的续景必须产生一个新的决定。
