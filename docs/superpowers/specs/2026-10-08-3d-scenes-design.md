# 3D 场景重做 · 设计规格（子项目 B）

> 日期：2026-10-08 · 状态：待评审
> 前置：子项目 A（550 风格界面外壳，规格 `2026-10-07-550-ui-shell-design.md`，提交 `0d31fe3`）已完成。
> 基线：`6b6eac6`。这一版包含另一会话加入的彩蛋（550A-Preview、笨笨）。

## 1. 背景与目标

子项目 A 之后，3D 画面已经铺满全屏，成为玩家视线的主体。可是现有场景是 M3 阶段做出来的程序化"能用版"。2026-10-08 我把 12 个场景逐一截图，看到的问题如下：

| 场景 | 问题 |
|---|---|
| 火星、地球全球 | 噪声贴图模糊，像卡通；地球大陆是虚构形状；火星大气边缘有错位重影 |
| 巡航飞船 | 几根圆柱加两块蓝板，高光过曝，没有任何细节 |
| 太阳粒子事件 | 粒子渲染成大块的橙色方点 |
| EDL | 看起来像一个发光的交通锥，认不出是穿越大气的着陆器 |
| 着陆点、基地 | 天空发白，地面一片平红；基地只有两根白圆柱加一个绿半球，而且正好躲在选项面板后面 |
| 沙尘暴 | 整屏红棕色，看不出风暴 |
| 上升 | 火箭在天空里只有一个小点 |
| 太阳系轨道 | 太阳光晕太大，像一团棉花；缺少信息标注 |

**目标**

1. 写实电影感：模型、材质、光照、天空、大气都要到"截图可以拿去展示"的水平。
2. 叠加 550 风格的全息标注，例如轨道线、目标框、扫描、轨迹、着陆椭圆，与子项目 A 的界面统一。
3. 按剧情编排镜头：每个剧情段落有自己的机位，镜头带缓慢推拉或跟踪，不再是同一个环绕镜头。
4. 构图避开界面：主体放在对话框和选项面板之外。
5. 保持比赛硬约束：离线单文件可以用 `file://` 直接打开；不向外部发请求；手机能玩；低配设备可降级。

**非目标**

- 不改 `src/core/`、`src/content/`，也就是不改剧情、数值、场景提示（SceneCue）的种类和章节结构。
- 不改界面外壳（子项目 A）。例外只有一处：`app.ts` 调用 `stage.setScene` 时多传一个段落 id。另外，`screens.ts` 的"玩法与依据"里要补一行素材出处。
- 不引入外部 3D 模型文件（glTF 等），所有模型都用代码构建。
- 不做音效改动。

## 2. 已确认的决策

| 项 | 决定 |
|---|---|
| 美术方向 | 写实为主，叠加全息标注（白色发丝线，红色强调） |
| 星球贴图 | 采用 NASA 公有领域真实影像（火星、地球），云层继续程序生成 |
| 镜头 | 按剧情编排：每个段落切到或缓动到下一个机位 |
| 建模方式 | three.js 代码建模，不加载外部模型文件 |

## 3. 素材

| 用途 | 文件 | 来源 | 原始大小 | 处理 | 署名 |
|---|---|---|---|---|---|
| 火星 | `Mars.jpg` | NASA 3D Resources，<https://science.nasa.gov/3d-resources/mars>（直链 `assets.science.nasa.gov/.../image/mars/Mars.jpg`） | 0.97 MB | 原样使用；如果宽度超过 4096 就缩到 4096 | NASA/JPL-Caltech（Viking 影像，USGS 处理） |
| 地球 | `world.topo.bathy.200412.3x5400x2700.jpg` | NASA Earth Observatory，Blue Marble Next Generation，2004 年 12 月 | 2.57 MB | 缩放到 4096×2048，JPEG 质量 85，约 1.5 MB | NASA Earth Observatory |

- **下载**：实现阶段下载前，先向用户列出文件名、来源和大小，得到确认后再下载（规则要求）。
- **存放**：处理后的文件放在 `src/assets/textures/mars.jpg` 和 `src/assets/textures/earth.jpg`。处理命令写在 `scripts/prep-textures.py`（依赖 Pillow），只运行一次，产物入库。
- **引入**：用 `import url from '.../mars.jpg'`。构建时 `assetsInlineLimit` 已设为 100 MB，图片会内联成 data URL，`file://` 下的 WebGL 纹理不会遇到跨域问题。
- **分档**：低画质档在加载时用 canvas 把贴图缩到 1024 宽，降低显存占用。
- **加载期间**：图片解码完成前，先用现有的程序贴图（`textures.ts`）占位，加载完成后替换，不阻塞首帧。
- **体积预算**：离线包 `dist/index.html` 不超过 6 MB（现在约 0.8 MB）。
- **署名**：同步写进 `README.md`、`docs/SCIENCE.md` 和"玩法与依据"。

### 4.2 接口变化

```ts
// stage.ts
export interface Stage {
  setScene(cue: SceneCue, s: MissionState | null, beat?: string): void; // beat：剧情段落 id，变化时推进镜头
  update(s: MissionState): void;
  previewSite(id: SiteId): void;
  setQuality(q: Settings['quality']): void;
  readonly tier: Tier | 'off';
}

// scenes/common.ts
export interface SceneModule {
  scene: THREE.Scene;
  camera: THREE.PerspectiveCamera;
  exposure: number;
  shots(cue: SceneCue): Shot[];       // 该提示下的机位序列，至少 1 个
  apply(s: MissionState | null, cue: SceneCue): void;
  tick(dt: number, t: number): void;  // 只更新场景内容，相机由导演控制
  onShot?(cue: SceneCue, index: number): void; // 切到新机位时调用，供场景启动对应的演出时间轴（如延迟回放）
  fx?: { sensorHits?: number };       // 后期参数（目前只有太阳粒子事件的传感器噪点）
  dispose(): void;
}
```

`app.ts` 的 `playBeat` 改为调用 `stage.setScene(cue, state, v.beat.id)`。章节切换时的那次调用不传 beat。

### 4.3 镜头导演（`director.ts`）

```ts
export interface Shot {
  from: Vec3; to: Vec3;              // 相机位置：起点 → 终点
  look: Vec3 | (() => THREE.Vector3); // 注视点；可以是函数，用来跟踪运动物体
  lookTo?: Vec3;                      // 可选：注视点也随时间移动
  fov?: number;                       // 默认 40
  dur?: number;                       // from → to 的运动时长（秒），默认 14
  ease?: 'inOut' | 'out' | 'linear';
  shake?: number;                     // 抖动幅度（EDL、上升用）
}
```

- **推进规则**：
  - `setScene` 的提示与上一次相同、且 beat 不同时，镜头推进到该提示机位列表的下一个，到末尾后循环。
  - 提示改变时，从第 0 个机位开始。
  - 场景类型改变时，镜头直接切换（配合子项目 A 的"信号重建"转场）。
  - 同一场景类型内换机位时，用 1.2 秒的缓动从当前位姿过渡到新机位的起点。
- **运动**：到达起点后，按 `dur` 从 `from` 运动到 `to`；运动结束后，以极小幅度的正弦漂移保持，画面不会完全静止。
- **安全区**：用 `camera.setViewOffset`，让投影中心（也就是注视点）落在指定的屏幕位置：
  - 桌面（视口宽度 900px 及以上）：(0.42W, 0.40H)。
  - 手机：(0.50W, 0.30H)。
  - 窗口尺寸变化时重新计算。这样所有机位的主体都会自动避开底部对话框和右下方的选项面板。

### 4.4 全息标注工具箱（`holo.ts`）

统一材质 `HoloMaterial`：采用加色混合，默认白色（`#e6e8ea`），强调色为红（`#ff3b30`）。材质带轻微闪烁和横向扫描带（着色器内按时间与屏幕 y 坐标计算），随距离淡出。所有元素都在 `tick` 里随时间动画。

| 构件 | 用途 |
|---|---|
| `holoRing(r, ticks)` | 带刻度的圆环：轨道、禁区、选址圈 |
| `holoArc(points, dashed)` | 轨迹弧线，可以带移动的光点：转移轨道、下降轨迹、上升轨迹、光子脉冲 |
| `holoLabel(text, opts)` | 文字标签，用 canvas 生成贴图的精灵，等宽字体，屏幕尺寸恒定，带引线 |
| `holoBracket(target)` | 跟随 3D 物体的屏幕空间角标框 |
| `holoGrid(w, h)` | 网格平面：基地规划、着陆椭圆 |
| `holoSweep(r)` | 旋转扫描扇面 |
| `holoGraticule(r)` | 经纬网球壳 |

标签文字规范与界面一致：英文编号用等宽大写（如 `UTOPIA PLANITIA`、`SUIHUO BASE`），中文名放在第二行。

### 4.5 环境光照（`env.ts`）

对每种场景，先用 canvas 生成一张小的等距柱状环境图，再用 `PMREMGenerator` 预过滤，赋给 `scene.environment`，让金属、隔热毯、玻璃有可信的反射。环境图内容分两类：深空用"星点 + 太阳方向亮斑 + 行星方向的弱反光"；火星地表用"天空渐变 + 地面色"。画质为"低"时不生成环境图，改用半球光。

## 5. 各场景设计

机位列表里的"段落"指同一场景提示下依次出现的 beat。下面坐标都是示意，实现时在截图评审中微调。

### 5.1 火星全球 `globe`（control）

- **星球**：NASA 火星贴图；用贴图亮度生成凹凸，强度适中。
- **大气**：重写为薄的尘埃色边缘。修复重影：大气球壳必须和星球共用同一个父节点，并且同心。
- **晨昏线**：用柔和的明暗交界线，太阳方向侧光。
- **全息**：经纬网球壳（不透明度 0.08）；三个候选着陆点各有一个竖向光柱和环形标记，并带标签（中英双语）；一个扫描扇面绕极轴缓慢旋转。
- **选址预览**（`previewSite`）：选中的着陆点标签与圆环改为红色，并加上角标框；星球转到该点朝向镜头。确定着陆点之后，只保留这一个标记。
- **机位**：①远景缓推，整个星球偏左上；②贴近边缘的弧线横移，露出大气层；③俯视选址区，在选址段落使用。
- **补充**：远处加火卫一小卫星，点缀用。

### 5.2 太阳系 `orbit`（orbit、conjunction）

- **太阳**：小而亮的核心，加镜头光晕（`Lensflare`，光晕贴图程序生成），去掉现在的巨大光晕。
- **轨道**：地球、火星轨道改为带刻度的全息环（白色）。地球和火星用真实贴图的小球，加上标签。
- **转移轨道**：红色虚线弧，飞船位置有光点和标签（`ZHURONG-1 · D+xx`）。
- **光速延迟**：地球与飞船（或火星）之间画一条通信线，线上光子脉冲按"真实延迟 × 压缩比例"移动，一次往返约 4 秒，标签显示"单程 x.x 分"。
- **日凌**：太阳与火星之间画出红色的"太阳干扰锥"，通信线变成红色虚线，标签显示 `SIGNAL LOST`。
- **机位**：①斜俯视全景；②低角度沿黄道面，太阳在画面边缘；③跟随飞船光点；日凌：④从地球后方看向太阳和火星。

### 5.3 地球 `earth`（launch、home）

- **星球**：Blue Marble 贴图；程序云层改用域扭曲 fbm，分辨率更高，在独立球壳上缓慢转动；用大气散射式着色器画出蓝色边缘和昼夜交界的暖色带；夜半球微微压暗。
- **发射**（launch）：从低轨道视角看南海地平线。文昌（19.6°N，110.9°E）位置升起一条火箭尾迹：发光的尾焰精灵加上逐渐弯曲的白色凝结尾迹。全息标签 `WENCHANG LC-101`，加上升轨迹弧。
- **回家**（home）：返回舱再入火流星从画面上方划向南海预定溅落区，溅落区有全息圆环和标签。
- **机位**：发射段为①地平线低轨横移、②跟随尾迹上升；回家段为③俯视南海、④跟随火流星。

### 5.4 巡航飞船 `ship`（cruise、spe）

**整船重新建模**，用 `Group` 组织，一共约 150 到 250 个网格，重复件用 InstancedMesh 实例化。各部分如下：

- **居住舱**：分段圆柱，带环肋和观察窗。观察窗使用自发光材质，内部是暖光。
- **节点舱**：带两个对接口。
- **桁架**：方形格构，用实例化细杆搭成。
- **散热板**：两组白色面板，带网格贴图。
- **太阳翼**：深蓝色电池片贴图，程序生成；金色框架，铰接臂。
- **着陆器**：对接在船头，70° 球锥气动外壳加金色多层隔热毯；隔热毯用程序褶皱法线和高金属度。
- **推进段**：发动机组，三个喷管，内壁暗红；巡航时不点火。
- **高增益天线**：碟形，始终指向地球方向。
- **航行灯**：红、绿、白三色闪烁。

**背景**：根据 `missionDay` 显示远处的地球或火星小圆盘，越接近火星，火星越大。太阳带镜头光晕。

**太阳粒子事件**（spe）：

- 高能粒子改为细长条状光线，用实例化四边形，按速度方向拉伸，代替方块点。
- 后期加一个"传感器击中"效果：随机出现单像素到数像素的白色亮点，模拟粒子打在相机传感器上。由 `fx.sensorHits` 控制强度。
- 舱内的风暴避难区（如果装了水墙，就是水墙位置）出现红色全息护罩，并配脉冲告警灯。

**机位**：①3/4 英雄机位缓推；②沿船体贴近横移，看清细节；③远景，船很小，背景是火星或地球；spe 段为④对着太阳方向的逆光机位。

### 5.5 进入、下降与着陆 `edl`（edl）以及 `landing` 开场

- **edl 段落 1（简报）**：远处是火星弧形地平线，用 NASA 贴图的大球，只显示局部。着陆器与巡航级分离，进入舱缓慢翻转，调整到进入姿态。全息：进入走廊（两条边界弧）和预定进入点标记。
- **edl 段落 2（预案，持续到决策结算）**：
  - 70° 球锥进入舱，防热罩朝前。
  - 等离子鞘套用菲涅尔辉光着色器，加噪声流动，粉橙色；尾流是两三条发光拖带。
  - 镜头轻微抖动。
  - 全息显示下降轨迹弧，弧上有高度刻度。
- **landing 第一个机位**（"延迟回放"）：按 14 秒的时间轴依次演出：
  1. 超声速降落伞展开：伞盘加伞绳；
  2. 防热罩分离并坠落；
  3. 动力下降：着陆器带四条腿，四台发动机喷焰；
  4. 地面扬尘扩散，扬尘用精灵群加上逐渐变淡的环形尘浪；
  5. 触地，尘埃落定。

  之后保持着陆器特写。全息：地面上显示着陆椭圆网格和落点标记。
- **着陆器模型**：与基地使用同一套部件风格，即金色隔热毯加白色舱体，带四条有缓冲器的腿。

### 5.6 火星地表 `surface`（landing、surface、storm、ascent）

- **天空**：重写着色器。白天是奶油黄到浅棕的渐变，地平线较亮；太阳周围是火星特有的蓝色日晕，太阳低时更明显。由 τ 控制整体变暗，以及向红棕色偏移的程度。
- **地形**：
  - 保留 MOLA 剖面驱动的高程。
  - 地面细节贴图提高到 1024（高、中档），内容包括碎石、裂纹、风纹。
  - 颜色按坡度和高度混合三到四种土色，碎石区偏深。
  - 远处加一圈台地和撞击坑缘，用低多边形加大气透视雾，形成层次感。
  - 岩石沿用实例化，但改为有长宽比的不规则形状，并带阴影。
- **基地**（`base.ts`）。布局以居住舱为原点，所有模块位置固定，便于镜头构图，也便于规划笨笨的巡检路线：
  - 主居住舱：充气式，带环肋，窗户在夜间和风暴中亮灯；气闸舱用连接管连通。
  - 太阳能阵列：装了才显示；位于南侧，有支架，会缓慢转动跟踪太阳。
  - Kilopower 反应堆：装了才显示；东北方向远处，圆柱堆芯加锥形散热片，外面一圈全息禁区圆环加标签。
  - 温室：装了才显示；穹顶，内部有植物生长灯，散发暖粉色光。
  - 加压漫游车：装了才显示。
  - 冰钻井架：装了才显示，并有转动的钻头。
  - 通信天线杆：带指向地球的碟形天线。
  - 风化层覆盖：装了才显示，呈土丘状覆盖居住舱。
  - 火星上升器：西北方向，分级箭体，有发射台。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 代码建模的工作量大，细节容易显得"玩具感" | 统一材质库（隔热毯、白色复合材料、深色金属、电池片），靠贴图和法线补细节；全息标注承担一部分信息量；截图评审及时纠偏 |
| 中低端设备掉帧 | 严格执行分档；实例化；粒子数随档位缩放；用 `renderer.info` 监控预算 |
| 安全区偏移在超宽或很矮的窗口里表现异常 | 偏移量按视口比例计算并限幅；对 1280×720、1440×900、390×844 三种尺寸截图检查 |
| 贴图内联后首屏变慢 | 图片异步解码，先显示程序贴图占位；离线包体积控制在 6 MB 以内 |
| 笨笨在新布局中穿模，或行为被改动 | 迁移时保留原有的模型、动作和参数，只改巡检路线；在截图评审中专门检查 |
| 另一个会话同时改动 `src/render/` | 已经协调：彩蛋会话的改动已在 `6b6eac6` 提交，它不再改 render；开工前再用 ListAgents 确认一次 |
