# 550 风格界面外壳 · 设计规格（子项目 A）

> 日期：2026-10-07 · 状态：待评审
> 范围：《光速之隔》表现层改版的第一个子项目。第二个子项目"3D 场景重做"（B）另写规格。

## 1. 背景与目标

用户试玩反馈：界面缺乏科幻感；左侧遥测面板一直占据屏幕；中间的 3D 画面不够精致；右侧通信频道一直罗列全部对话。希望参考《流浪地球 2》中 550 系列量子计算机的界面风格，并把对话改成游戏中常见的"底部大对话框、一次一句、点击继续或回应"。

**目标**

1. 3D 画面全屏铺开，界面只保留顶部状态条和底部对话框，提升沉浸感。
2. 对话改为逐句推进的对话框，决策选项在对话框上方出现。
3. 统一采用 550 式的视觉语言：黑底、冷白色发丝线、角标框、等宽数字、信号红强调。
4. 手机竖屏可以完整游玩，页面不出现横向滚动（比赛硬性要求）。

**不做的事（非目标）**

- 不改 `src/core/`（状态、流程、数值、结局）和 `src/content/`（剧情、台词）。
- 不改 `src/render/` 的 3D 场景内容，这部分属于子项目 B。本子项目只在 3D 画面外面加一层 DOM 叠层（取景框、扫描线、转场效果）。
- 不引入 UI 框架，继续使用原生 DOM 加 CSS，以及 `ui/dom.ts` 里的 `h()` 辅助函数。
- 不直接使用片中的"MOSS""550W"名称和红色圆眼标志。游戏内的计算机命名为"燧火任务核心 QC-01"。

## 2. 已确认的决策

| 项 | 决定 |
|---|---|
| 子项目拆分 | A 界面外壳先做；B 3D 场景重做后做 |
| 配色 | 冷白加信号红：纯黑底，冷白色发丝线，红色只用于强调和危险，琥珀色只用于预警 |
| 遥测 | 顶部状态条放五维迷你仪表，完整遥测放进左侧抽屉，按需呼出 |
| 对话 | 底部对话框逐句显示，带打字机效果；支持自动模式 |
| 历史 | 保留"通信记录"，通过按钮或 L 键打开全屏记录 |
| 大型决策 | 配载、着陆点、预案卡、授权度仍用全屏面板，只换风格 |

**对评审时说法的一处修正**：评审中说过"按 Tab 键呼出抽屉"。但 Tab 是键盘用户在按钮之间移动焦点的标准按键，劫持它会破坏无障碍操作。因此改为 **T 键**（Telemetry 的首字母）。点击状态条同样可以开关抽屉。

## 3. 屏幕结构

### 3.1 桌面端（宽度 900px 及以上）

```
┌──────────────────────── 状态条 .topbar（高约 44px）───────────────────────┐
│ 光速之隔 // QC-01 │ 第二章 · 深空 │ [时间][能源][物资][人员][安全] │ ◉ 延迟 11.5 分 │ 图标 │
├──────────────────────────────────────────────────────────────────────────┤
│ ┌ CAM-03 / 祝融一号                                  火星时间 T−11:32 ┐ │
│   地火转移轨道 · 巡航（段落标题）                              SIG ▮▮▮▮▯   │
│                                                                          │
│                       （3D 全屏，叠一层淡扫描线）                         │
│                                              ┌ 选项面板 .choices ───────┐ │
│                                              │ 1 立即进入风暴避难舱  8–14%│ │
│                                              │ 2 等待下一组遥测确认 18–35%│ │
│                                              └──────────────────────────┘ │
│ ┌ 对话框 .dialogue ──────────────────────────────────────────────────┐ │
│ │ [头像] 林照 · 燧火-1 · 指令长 · T−11:32            [记录 L] [自动 A]│ │
│ │        台词正文，以打字机效果逐字出现……                          ▼ │ │
│ └────────────────────────────────────────────────────────────────────┘ │
└ 取景框四角角标 ─────────────────────────────────────────────────────────┘
```

- `#scene`（3D 画布）保持 `position:absolute; inset:0`，铺满整个视口。
- 对话框水平居中，最大宽度 1180px，距底部 16px，最小高度 132px，高度随文字自动增长，最高 40vh，超出部分在框内滚动。
- 选项面板贴着对话框上沿、靠右对齐，宽度为 `min(560px, 100% - 32px)`。最大高度等于视口高度减去状态条、对话框和间距，超出部分在面板内滚动。
- 遥测抽屉 `.drawer` 宽 340px，从左侧滑入，背后有一层半透明遮罩。点击遮罩、按 Esc 或按 T 都能关闭。

### 3.2 手机端（宽度 900px 以下）

- `body` 不再滚动，`#app` 固定铺满屏幕，3D 画面作为全屏背景。
- 状态条分两行：第一行是章节名、延迟读数和"≡"菜单按钮；第二行是五条细仪表。原来的图标按钮（知识档案集、玩法与依据、音效、设置、项目仓库）全部收进"≡"弹出菜单。通信记录的入口只在对话框上，不放进菜单。
- 对话框贴底并占满宽度，左右各留 8px 边距。头像缩小到 44px。
- 选项面板位于对话框上方，占满宽度，最大高度 50dvh，超出部分滚动。
- 遥测抽屉改为全屏面板。
- 取景框的读数只保留左上角的场景名，右上角的时间码隐藏。
- 底部为 `env(safe-area-inset-bottom)` 留出安全区。

## 4. 对话框交互规则

### 4.1 "闸门"模型

对话框任何时刻只显示一句话，记为"当前句"。它有四种状态：`空`、`打字中`、`已显示`、`已确认`。

- 显示一句新台词之前，必须先确认上一句。如果上一句处于`已显示`状态，就等待玩家推进（点击对话框、按空格或回车）；自动模式下改为等待阅读计时结束。
- 在`打字中`状态推进，会立即显示整句，状态变为`已显示`，此时不会跳到下一句。
- `play(lines)` 在**最后一句打字完成**后立即返回，不等待确认。最后一句由调用方决定怎么收尾：
  - 后面没有决策：调用 `waitContinue()`，右下角的 ▼ 换成"继续 ▶"按钮（无障碍名称为"继续"），玩家推进后结束。
  - 后面有决策：调用 `prompt(text)` 显示提问句，再展示选项。玩家选中选项，就视为确认了提问句。

这样，玩家读完每一句都恰好只需要点击一次。打字过程中多点的一次只用于跳过打字，不会因为点快了而漏掉台词。

### 4.2 不同类型台词的呈现

| 类型 | 判定 | 呈现 |
|---|---|---|
| 火星乘员 | `CAST[speaker].onMars` 为真且延迟大于 0.2 分钟 | 先显示约 0.4 秒的"接收中 · 信号经 X 分钟抵达"和一段波形，推进可跳过；随后打字。元信息为姓名、呼号、角色和 `T−mm:ss`；日凌期间元信息显示"日凌 · 延迟记录" |
| 地面人员 | 其余说话人 | 直接打字，元信息显示"地面" |
| 系统遥测 | `speaker === 'sys'` | 不显示头像，用等宽字体，前缀"◆ 遥测"。`tone: 'alert'` 时边框闪红并播放 `sfx('alert')`；`calm` 用白色，`cold` 用灰色 |
| 你的指令 | `you(text)` | 头像为"你"，元信息显示"上行 · 约 mm:ss 后抵达火星"。文字下方播放一段约 0.8 秒的上行进度条动画（只是装饰，不阻塞流程） |
| 决策提问 | `prompt(text)` | 元信息显示"决策 · 等待你的指令"，正文为提问内容 |

带 `tone` 的台词沿用现有的文字色调：alert 用浅橙，cold 用斜体灰，warm 用暖白。

### 4.3 速度与自动模式

- 打字速度：基准为每秒 40 字，再乘以设置中的速度系数（慢 0.6、正常 1、快 2.2）。
- **自动模式**：通过 A 键或对话框右上角的按钮切换，状态写入 `Settings.auto`（新增字段，默认关闭）。开启后，每句停留 `(350 + 字数 × 22) / 速度系数` 毫秒再自动推进，这是原 `comms.ts` 的节奏。带配音的台词会等语音播完，最多等 15 秒。
- **极速模式**（`?fast=1` 或 `speed: 'instant'`，供 e2e 测试使用）：打字立即完成，闸门立即放行。只有 `waitContinue()` 和决策仍然需要真正点击。
- 设置了 `prefers-reduced-motion` 时，打字立即完成，"接收中"动画也不播放。
- 推进到下一句时调用 `stopVoice()`。每句开始时播放 `sfx('blip')`，系统告警句改为播放 `sfx('alert')`。

### 4.4 决策

- **普通选择**（`choice`）：先调用 `prompt(d.prompt)`，再在 `.choices` 面板里渲染选项。每个选项是一个 `button.opt`，包含编号徽标（1–4）、标题、后果说明、风险区间条，以及"ⓘ 科学依据"展开按钮；不可选的选项显示锁定原因。按数字键 1–4 可以直接选择。选中后清空面板。
- **大型决策**（`loadout`、`site`、`presets`、`autonomy`）：调用 `prompt()`，提问文字用 `d.prompt`，没有时用默认文案（如"配载清单已就绪，等待你的确认"）。`.choices` 里放一个"打开配载清单"之类的重开按钮，同时自动弹出全屏面板（与现状一致）。
- **指令上行**（`command`）：`.choices` 里只放一个"发送自检指令"按钮。点击后，对话框正文区域临时替换为上行轨道动画（"地球 · 北京 → 火星 · 中继星「烽燧」"，计时规则与现在相同）。回执返回地球后，正文区域恢复，流程继续。

### 4.5 通信记录（`ui/backlog.ts`）

- 记录本局会话中的每一条消息：分隔标题、台词、你的指令、系统消息、决策提问。记录只保存在内存里，不写入存档。
- 从存档恢复时，记录以"从存档恢复"分隔标题开头。
- 打开方式：对话框右上角的"记录"按钮（无障碍名称为"通信记录"，全界面只有这一个同名按钮）或 L 键。状态条上不设通信记录的入口，避免出现两个同名按钮。打开后是全屏 `.overlay`，复用原 `comms.ts` 的消息列表样式（头像、元信息、时间戳），并自动滚动到底部。按 Esc 或"关闭"按钮关闭。

### 4.6 键盘

| 键 | 作用 | 生效条件 |
|---|---|---|
| 空格、回车 | 推进对话 | 没有打开任何覆盖层或抽屉；焦点在按钮上时，回车交给按钮自己处理 |
| 1–4 | 选择对应选项 | 同上 |
| A | 切换自动模式 | 同上 |
| L | 打开通信记录 | 同上 |
| T | 开关遥测抽屉 | 没有打开覆盖层 |
| Esc | 关闭抽屉、通信记录或"≡"菜单 | 对应的界面已打开 |

焦点在文本输入框里时，以上按键一律不处理。目前游戏里没有输入框，这条是预防性规则。

## 5. 视觉语言

### 5.1 设计令牌（`:root`）

```
--bg: #000;                 --panel: rgba(0,0,0,.78);      --panel-solid: #050607;
--line: rgba(220,224,230,.22);   --line-2: rgba(220,224,230,.5);   --line-3: rgba(220,224,230,.85);
--text: #e6e8ea;   --muted: #a9aeb4;   --dim: #7b8187;
--signal: #ff3b30;            /* 强调、危险、告警 */
--signal-dim: rgba(255,59,48,.18);
--warn: #ffb020;              /* 仅用于预警 */
--ok: var(--text);            /* 正常状态即白色，保持界面接近单色 */
--mars: #e0703a;              /* 仅用于火星相关的数据图形（剖面、着陆点） */
--radius: 2px;
```

状态的颜色规则：正常为白色，预警为琥珀色，危险为红色。原来的青色、绿色、紫色全部撤掉；乘员"留守"状态改用 `--muted` 加文字标注。

### 5.2 字体

- 正文沿用现有的中文字体栈 `--font`。对话框正文 17px（手机 16px），行高 1.7。
- 数字、编号、标签、时间码使用 `--mono`。英文标签（如 `TELEMETRY`、`CAM-03`、`CHAPTER 02`）字号 11–12px，字间距 0.18em。
- 只用 400 和 600 两种字重。

### 5.3 构件

- **`.frame` 角标框**：1px `--line` 边框，四角用 `::before` 和 `::after` 画出 10px 长的 `--line-3` 角标。激活时（`.frame.active`）左上角多一道 48×2px 的 `--signal` 短线。所有面板、卡片、对话框、抽屉都使用这个构件。
- **进场动画 `scanIn`**：220ms，`clip-path` 从中线向上下展开，期间透明度闪动 1 到 2 次。设置了 `prefers-reduced-motion` 时直接显示。
- **扫描线**：在 `#scene` 上叠一个 `.scanlines` 层，用 `repeating-linear-gradient` 画 1px 亮线（每 3px 一条，亮度约 3.5%），外加暗角。该层不响应鼠标（`pointer-events:none`）。
- **按钮**：主按钮为白色发丝线框配白字，悬停时底色变成 `--signal-dim`、边框变成 `--signal`；危险操作同样使用 `--signal`。去掉原来的橙色渐变。

### 5.4 取景框（`ui/frame.ts`）

- 屏幕四角有角标。桌面端的角标避开状态条，位于其下方。
- **左上角**：机位编号 `CAM-0n`（按场景类型固定编号：`globe` 为 01，`orbit` 为 02，`ship` 为 03，`edl` 为 04，`surface` 为 05，`earth` 为 06），加上场景名（原 `CAPTIONS` 文案）和当前段落标题。这一块取代原来左下角的 `.scene-caption`。
- **右上角**（仅桌面端）：时间码"任务日 D+n · 火星时间 T−mm:ss"，每秒刷新一次，秒数在延迟值附近循环走动，只是一种示意。下方是信号格，延迟越大格数越少；日凌期间显示红色的"SIG LOST"。
- **转场效果 `glitch()`**：场景类型（`sceneKind(cue)`）变化时触发，持续约 400ms。效果是 3 到 4 条横向错位亮条，加上整体亮度闪烁，正好覆盖 `Stage` 自带的 300ms 淡入淡出。设置了 `prefers-reduced-motion` 时不播放。

### 5.5 各个画面

- **标题页**：
  - 进入时先播开机自检，4 行等宽文字，总长不超过 1.2 秒：
    - `QC-01 燧火任务核心 · 量子飞控系统`
    - `链路自检 ……… 正常`
    - `深空网 · 烽燧中继 ……… 在线`
    - `载入任务档案：祝融一号`
  - 自检过后显示标题。点击或按键可以跳过自检；`?fast=1` 和设置了 `prefers-reduced-motion` 时直接跳过。
  - 菜单按钮在自检期间就已经在 DOM 里，只是淡入。e2e 测试依靠 Playwright 的自动等待，不需要改动。
  - 标志是原创的 SVG：左边一个小地球，右边一个小火星，中间一条虚线光路，下方标注 `11.5 LIGHT-MIN`。
  - 菜单文案和按钮名称不变。
- **章节卡**：先打出 `CHAPTER 0n // 标题`，然后显示副标题，本章要学的机制放在 `.frame` 框里。"开始"按钮一出现就可以点。
- **章节结算、结局、知识档案集、玩法与依据、设置、知识档案卡、配载、着陆点、预案卡、授权度**：只换风格，换成 `.frame` 和新令牌，DOM 结构与类名保持不变。着陆点剖面和资源曲线的图表配色要换成新色板，`charts.ts` 里的 `SERIES` 颜色相应调整。曲线需要区分五条线：白色、浅灰、琥珀、红色、`--mars`，每条线配不同的线型（实线或虚线）。
- **状态条 `.topbar`**：从左到右依次是品牌名 `光速之隔 // QC-01`、章节名、五格仪表、延迟读数（带脉冲点）、图标按钮。五格仪表的内容如下：

  | 格 | 主读数 | 条 |
  |---|---|---|
  | 时间 | `D+n` 或 `T−n` | 当前阶段（巡航、地表、返程）已经过的比例；发射前的地面阶段为满格 |
  | 能源 | 在火星地表时显示储能百分比，否则显示"正常" | 储能比例；不在地表时为满格 |
  | 物资 | 氧、水、食物中最少的天数 | 最少天数除以 600 |
  | 人员 | 在任人数 `n/4` | 平均健康 |
  | 安全 | 系统完好度 `%` | 系统完好度 |

  每一格按 `level()` 判定颜色。和上次刷新相比，数值变差时这一格闪烁 1.2 秒，并显示 `▼n`；变好时显示 `▲n`，不闪烁。点击任意一格都能打开抽屉。
- **遥测抽屉**：内容沿用 `Hud.render()` 的六张卡（时间、能源、物资、乘员、安全、任务产出），换成新风格。无论抽屉是否打开，每次 `refresh()` 都会重新渲染，以保证数据一致。

## 7. 无障碍

- 对话框正文的可见部分（打字效果）设置 `aria-hidden`。另放一个视觉隐藏、`aria-live="polite"` 的元素，每句开始时把整句写进去，这样读屏软件不会读出打到一半的文字。
- 抽屉、通信记录、"≡"菜单都是 `role="dialog"`：打开时焦点移进去，关闭时焦点回到触发它的按钮。
- 所有可点击元素的点击区域不小于 44×44px（手机端选项卡片、状态条格子都适用）。
- 文字和背景的对比度：`--text` 和 `--muted` 在黑底上满足 AA 标准；`--dim` 只用于辅助标签。
- 设置了 `prefers-reduced-motion` 时，关闭打字效果、闪烁、扫描进场和转场效果。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 每句都要点击，节奏比原来慢，单局可能超过 25 分钟 | 提供自动模式，打字速度也可以调；手动试玩时计时，必要时把默认速度调到"快" |
| 动态台词过长，对话框高度暴涨，挡住 3D 画面 | 对话框最高 40vh，超出部分在框内滚动；e2e 第 8 项会检查溢出 |
| 手机端选项很多（带依据和风险条），挤占屏幕 | 选项面板最大高度 50dvh，超出部分在面板内滚动；"科学依据"默认折叠 |
| 拆分 CSS 后，离线单文件包的内联可能出问题 | 在 `main.ts` 里静态 `import` 各个 CSS 文件，由 vite-plugin-singlefile 内联；跑离线 e2e 测试验证 |
| 扫描线、转场等效果在低端设备上掉帧 | 这些效果都是静态 CSS 或短暂的动画，不接入 WebGL 后期处理；手动在低画质下验证 |
